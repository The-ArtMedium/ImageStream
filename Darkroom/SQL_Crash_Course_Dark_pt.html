1. O que é SQL?

📂 Banco de dados: photography_db

SQL significa Structured Query Language (linguagem de consulta estruturada). É a linguagem que você usa para falar com um banco de dados — para fazer perguntas, obter dados, adicionar novos registros, ou fazer alterações.

Nosso banco de dados se chama photography_db. Contém fotógrafos de 20 países, suas sessões ao redor do mundo, e o equipamento que possuem. Estes são os mesmos dados usados no curso de Python — dois idiomas, um conjunto de dados.

Termos-ChaveUm banco de dados é uma coleção de dados organizados. Uma tabela é um conjunto de dados relacionados dentro dele. Uma linha é um registro. Uma coluna é um dado sobre esse registro.

2. SELECT — Ler Dados

📂 Tabela: photographers

O comando SQL mais importante é SELECT. Você o usará em quase toda consulta que escrever. Ele diz ao banco de dados quais colunas você quer ver.

-- Obter todas as colunas da tabela photographers SELECT * FROM photographers;
-- Obter apenas o nome e o país SELECT name, country FROM photographers;
Resultado
namecountry
Amara DialloSenegal
Carlos MendezBrazil
Priya NairIndia
James OkonkwoNigeria
-- Renomear uma coluna no resultado usando AS SELECT name AS photographer, specialty AS type_of_work, rating FROM photographers;
Use * com moderação. SELECT * retorna todas as colunas. Está tudo bem para explorar, mas em consultas reais liste apenas as colunas que você realmente precisa.
Prática

Escreva consultas que retornem:

  1. O nome e a câmera de cada fotógrafo
  2. Todas as colunas de photographers — use *
  3. Nome, especialidade e years_experience — renomeie years_experience como experience

3. WHERE — Filtrar

📂 Tabela: shoots

WHERE filtra seus resultados. Em vez de cada linha, você obtém apenas as linhas que correspondem à sua condição. Pense nisso como a pergunta depois de «mostre-me apenas...».

-- Somente as sessões em Dakar SELECT event, location, year FROM shoots WHERE location = 'Dakar';
-- Somente as sessões depois de 2020 SELECT event, year, photos_taken FROM shoots WHERE year > 2020;
-- Combinar duas condições com AND SELECT event, location, year FROM shoots WHERE location = 'Dakar' AND year > 2020;
Resultado
eventlocationyear
Urban PortraitsDakar2024
Coastal Landscape SeriesDakar2024
Urban ArchitectureDakar2023
Conceptual SeriesDakar2023
Sunrise SeriesDakar2024
Operadores disponíveis= (igual)  ·  != (diferente)  ·  > < >= <= (comparações)  ·  AND / OR (combinar)  ·  LIKE (correspondência de padrão)  ·  IN (lista de valores)
-- LIKE — correspondência parcial (% é um curinga) SELECT name, country FROM photographers WHERE name LIKE 'S%'; -- IN — corresponde a qualquer valor de uma lista SELECT name, country FROM photographers WHERE country IN ('USA', 'Brazil', 'Nigeria');
Valores de texto precisam de aspas. Números não. WHERE location = 'Dakar' — WHERE year > 2020. Misture-os e você terá um erro.

4. ORDER BY — Ordenar

📂 Tabela: shoots

ORDER BY ordena seus resultados. Por ano, por nome, por número de fotos. Crescente (A→Z, mais antigo→mais recente) ou decrescente (mais recente→mais antigo, mais alto→mais baixo).

-- Sessões mais recentes primeiro SELECT event, location, year FROM shoots ORDER BY year DESC;
-- Sessões com mais fotos tiradas, as mais altas primeiro SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC;
-- Ordenar por duas colunas — ano primeiro, depois nome do evento SELECT event, location, year FROM shoots ORDER BY year DESC, event ASC;
Resultado
eventlocationyear
Bridal SessionKyiv2024
City NightsAccra2024
Coastal Landscape SeriesCasablanca2024
Coastal Landscape SeriesDakar2024
ASC = crescente (padrão, do menor para o maior, A a Z). DESC = decrescente (do maior para o menor, Z a A). Na dúvida, adicione DESC para ver os valores mais recentes ou mais altos primeiro.

5. LIMIT & DISTINCT

📂 Tabela: shoots · photographers

Dois pequenos comandos que você usará constantemente. LIMIT controla quantas linhas você recebe de volta. DISTINCT remove valores duplicados.

LIMIT

-- Mostrar apenas as 5 sessões mais recentes SELECT event, location, year FROM shoots ORDER BY year DESC LIMIT 5;
-- A única sessão com mais fotos tiradas SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC LIMIT 1;

DISTINCT

-- Quais países estão representados? (sem duplicatas) SELECT DISTINCT country FROM photographers ORDER BY country;
-- Quais locais foram usados para sessões? SELECT DISTINCT location FROM shoots ORDER BY location;
Resultado
location
Accra
Beirut

Bogotá
Cairo
Sempre use LIMIT ao explorar uma tabela pela primeira vez. Mesmo com 103 linhas isso mantém sua tela legível — e o hábito importa ainda mais quando seu arquivo real crescer para os milhares.

6. COUNT, AVG, MIN, MAX

📂 Tabela: shoots · photographers

Funções agregadas calculam valores através de múltiplas linhas. Em vez de ver linhas individuais, você obtém um único número resumo. Essencial para entender seu arquivo em escala.

-- Quantas sessões no banco de dados? SELECT COUNT(*) AS total_shoots FROM shoots; -- Média de fotos tiradas por sessão SELECT AVG(photos_taken) AS avg_photos FROM shoots; -- Maior e menor número de fotos em uma única sessão SELECT MAX(photos_taken) AS biggest_shoot, MIN(photos_taken) AS smallest_shoot FROM shoots;
Resultado
total_shootsavg_photosbiggest_shootsmallest_shoot
1036001,186119
-- Total de fotos exportadas em todas as sessões SELECT SUM(photos_exported) AS total_exported FROM shoots; -- Quantos fotógrafos têm avaliação acima de 4.0? SELECT COUNT(*) AS top_rated FROM photographers WHERE rating > 4.0;
SUM · AVG · MAX · MIN · COUNT — essas cinco funções respondem a maioria das perguntas do mundo real sobre seu arquivo. Quanto? Quantos? Qual é o melhor? Qual é o pior?

7. GROUP BY & HAVING

📂 Tabela: shoots · photographers

GROUP BY agrupa linhas para que você possa contar, somar ou tirar a média por categoria. Em vez de «quantas sessões no total» você obtém «quantas sessões por ano» ou «por local».

-- Quantas sessões por ano? SELECT year, COUNT(*) AS shoots_that_year FROM shoots GROUP BY year ORDER BY year DESC;
Resultado
yearshoots_that_year
2024312
2023298
2022341
2021276
-- Média de fotos por sessão, agrupada por local SELECT location, COUNT(*) AS total_shoots, ROUND(AVG(photos_taken), 0) AS avg_photos FROM shoots GROUP BY location ORDER BY total_shoots DESC;

HAVING — filtrar depois de agrupar

WHERE filtra linhas antes de agrupar. HAVING filtra grupos depois de agrupar. Use HAVING quando sua condição envolver uma função agregada.

-- Somente locais com mais de 5 sessões SELECT location, COUNT(*) AS shoot_count FROM shoots GROUP BY location HAVING COUNT(*) > 5 ORDER BY shoot_count DESC;
A regraToda coluna no SELECT que não está dentro de uma função (COUNT, SUM, AVG) deve aparecer no GROUP BY. Se você seleciona, agrupe.
WHERE vs HAVING: WHERE filtra linhas antes do grupo ser formado. HAVING filtra os grupos depois de formados. Na dúvida — se sua condição usa COUNT, SUM, AVG — use HAVING.

8. JOIN — Duas Tabelas

📂 Tabelas: photographers · shoots

JOIN conecta duas tabelas usando uma coluna compartilhada. É aqui que o SQL se torna verdadeiramente poderoso — ligando o nome de um fotógrafo a todas as suas sessões, através de duas tabelas separadas.

-- Conectar sessões aos nomes dos fotógrafos SELECT photographers.name, shoots.event, shoots.location, shoots.year FROM shoots JOIN photographers ON shoots.photographer_id = photographers.photographer_id ORDER BY shoots.year DESC LIMIT 5;
Resultado
nameeventlocationyear
Amara DialloWildlife Reserve ShootKyiv2024
Carlos MendezUrban PortraitsSão Paulo2024
Carlos MendezMarket DayBerlin2024
Carlos MendezStreet Life SeriesLisbon2024
-- Usar alias de tabela para deixar as consultas mais curtas SELECT p.name, s.event, s.year, s.photos_taken FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id WHERE s.year >= 2022 ORDER BY s.photos_taken DESC;
A chave compartilhadashoots.photographer_id corresponde a photographers.photographer_id. Essa coluna compartilhada é o que conecta as duas tabelas. Sem ela, o JOIN não tem nada para corresponder.
Alias de tabela — dê a cada tabela uma letra curta (p para photographers, s para shoots). Isso torna consultas longas muito mais fáceis de ler e escrever.

9. Múltiplos JOINs

📂 Tabelas: photographers · shoots · equipment

Você pode fazer JOIN de mais de duas tabelas em uma única consulta. Cada JOIN adiciona mais uma conexão. A chave é sempre uma coluna compartilhada entre duas tabelas.

-- Fotógrafos + suas sessões + o equipamento usado SELECT p.name AS photographer, s.event, s.year, e.brand || ' ' || e.model AS camera FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id JOIN equipment e ON e.photographer_id = p.photographer_id WHERE e.type = 'Camera' ORDER BY s.year DESC LIMIT 10;
Resultado
photographereventyearcamera
Amara DialloWildlife Reserve Shoot2024Sony A7 IV
Sofia ReyesCoastal Landscape Series2024Nikon Z7 II
Carlos MendezRio Street Series2023Sony A7 IV
-- Quantos itens de equipamento cada fotógrafo possui? SELECT p.name, COUNT(e.item_id) AS gear_count, SUM(e.purchase_price_usd) AS total_invested FROM photographers p JOIN equipment e ON e.photographer_id = p.photographer_id GROUP BY p.name ORDER BY total_invested DESC;
Cada JOIN é mais uma ponte. Primeira ponte: shoots → photographers. Segunda ponte: equipment → photographers. A ordem importa — cada nova tabela deve compartilhar uma coluna com uma já presente na consulta.

10. Subconsultas

📂 Tabelas: photographers · shoots

Uma subconsulta é uma consulta dentro de outra consulta. Ela permite usar o resultado de uma pergunta como entrada para outra. A consulta interna executa primeiro e passa seu resultado para a consulta externa.

-- Encontrar todas as sessões acima da média de fotos SELECT event, location, photos_taken FROM shoots WHERE photos_taken > ( SELECT AVG(photos_taken) FROM shoots ) ORDER BY photos_taken DESC;
-- Fotógrafos que fizeram mais de 5 sessões SELECT name, country, specialty FROM photographers WHERE photographer_id IN ( SELECT photographer_id FROM shoots GROUP BY photographer_id HAVING COUNT(*) > 5 );

Prática

Tente escrever estas subconsultas:

  1. Encontre todos os fotógrafos com avaliação acima da média
  2. Encontre sessões onde photos_exported é maior que a média geral
  3. Encontre fotógrafos que possuem equipamento custando mais de $5.000 no total

11. INSERT & UPDATE

📂 Tabelas: photographers · shoots

Tudo até agora foi ler dados. INSERT adiciona novas linhas. UPDATE muda as existentes. Esses são os comandos que você usa para manter seu arquivo atualizado.

INSERT — adicionar um novo registro

-- Adicionar uma nova sessão ao banco de dados INSERT INTO shoots (photographer_id, event, location, year, photos_taken, photos_exported) VALUES (1, 'Nairobi Wildlife Assignment', 'Nairobi', 2025, 710, 115);
-- Adicionar um novo fotógrafo INSERT INTO photographers (name, country, specialty, years_experience, rating) VALUES ('Grace Mwangi', 'Kenya', 'Wildlife', 8, 4.3);

UPDATE — alterar dados existentes

-- Atualizar a avaliação de um fotógrafo UPDATE photographers SET rating = 4.8 WHERE photographer_id = 1; -- Atualizar photos_exported para uma sessão específica UPDATE shoots SET photos_exported = 112 WHERE shoot_id = 4471;
Sempre use WHERE com UPDATE. Sem WHERE, o UPDATE se aplica a todas as linhas da tabela. Isso quase nunca é o que você quer. Verifique sua condição WHERE com um SELECT antes de executar um UPDATE.
