Como pensar antes de digitar

Você já sabe
como consultar

Antes de aprender a sintaxe do SQL, entenda isto: você tem consultado dados a vida inteira. Toda vez que você fez uma pergunta sobre um grupo de coisas, você estava fazendo o que um banco de dados faz.

Você pensa
"Mostre-me todos os fotógrafos de retrato com nota acima de 4.5"
SELECT name, rating
FROM photographers
WHERE specialty = 'Portrait'
  AND rating > 4.5;
Você pensa
"Quem são os 3 que mais ganharam este ano, ordenados por total de tarifas?"
SELECT photographer_id, SUM(fee_usd)
FROM shoots
GROUP BY photographer_id
ORDER BY SUM(fee_usd) DESC
LIMIT 3;
Você pensa
"Quais especialidades têm mais de dois fotógrafos?"
SELECT specialty, COUNT(*)
FROM photographers
GROUP BY specialty
HAVING COUNT(*) > 2;
Você pensa
"Me dê todas as sessões em Lagos ou Nairóbi ordenadas pelas mais recentes"
SELECT * FROM shoots
WHERE location IN ('Lagos', 'Nairobi')
ORDER BY year DESC;
A mudança de mentalidade

SQL não exige que você pense como um programador. Exige que você pense como alguém fazendo uma pergunta clara sobre informação organizada. Se você conseguir formular a pergunta em linguagem simples primeiro, o SQL quase se escreve sozinho.

O diagrama mais importante em SQL

A ordem em que você escreve
não é a ordem em que ele executa

Esse único mal-entendido causa mais confusão do que qualquer outro em SQL. Você escreve uma consulta em uma ordem. O banco de dados a executa em uma ordem completamente diferente. Assim que você vê isso, as mensagens de erro começam a fazer sentido.

A ordem em que você escreve
1
SELECT
quais colunas
2
FROM
qual tabela
3
WHERE
filtrar linhas
4
GROUP BY
agrupar linhas
5
HAVING
filtrar grupos
6
ORDER BY
ordenar resultados
7
LIMIT
quantas linhas
⟹
A ordem em que o banco de dados executa
1
FROM
buscar a tabela primeiro
2
WHERE
remover linhas que não correspondem
3
GROUP BY
formar os grupos
4
HAVING
remover grupos que não correspondem
5
SELECT
agora escolher as colunas
6
ORDER BY
ordenar o que resta
7
LIMIT
reduzir ao número certo
Por que isso importa — três coisas que isso explica imediatamente
  • Por que você não pode usar um alias do SELECT dentro do WHERE — o SELECT ainda não foi executado quando o WHERE executa
  • Por que WHERE não pode usar COUNT() ou AVG() — esses são calculados no SELECT, que executa depois
  • Por que HAVING existe — ele executa depois do GROUP BY, então pode filtrar usando resultados agregados que o WHERE nunca vê
Uma pergunta que vale a pena fazer

O HAVING pode existir
sem GROUP BY?

Sim. E entender por quê revela que você realmente compreende o que o GROUP BY faz — não só onde digitá-lo.

O que acontece sem GROUP BY

Quando não há GROUP BY, a tabela inteira é tratada como um único grupo. Cada linha pertence a esse único grupo. Então o HAVING se aplica à tabela toda como se fosse uma.

Esta consulta é tecnicamente válida:

SELECT COUNT(*) AS total
FROM photographers
HAVING COUNT(*) > 5;

Ela pergunta: a tabela photographers inteira tem mais de 5 linhas? Se sim, retorna a contagem. Se não, não retorna nada. Quase nunca é o que você realmente quer — mas funciona, e saber por que funciona significa que você entende a base.

Tecnicamente válido
HAVING sem GROUP BY trata a tabela toda como um único grupo. A consulta vai executar sem erro.
Quase nunca útil
Se você se encontrar escrevendo HAVING sem GROUP BY, quase certamente você quer WHERE em vez disso — ou precisa adicionar um GROUP BY.
O teste de fundamentos

Se alguém te perguntar «o HAVING pode existir sem GROUP BY?» e você conseguir responder com clareza — você entende a ordem de execução. Isso significa que WHERE, HAVING, GROUP BY, e funções agregadas nunca mais vão te confundir. Essa é a base. Tudo o mais é só sintaxe.

Dois idiomas, um objetivo

SQL e Python —
não rivais, parceiros

Você vai aprender os dois nesta série. Eles não estão competindo. São ferramentas que trabalham juntas, e a maioria dos analistas de dados usa ambos todos os dias.

LinguagemO que fazQuando usar
SQLFala diretamente com bancos de dados — faz perguntas, recupera, filtra, agrupa dados armazenados em tabelasQuando seus dados vivem em um banco de dados e você precisa extraí-los ou resumi-los
PythonUma linguagem de programação geral — pode fazer quase tudo, incluindo carregar arquivos, analisar dados, e desenhar gráficosQuando você tem os dados e quer remodelá-los, calcular, visualizar, ou automatizar coisas com eles
O fluxo de trabalho do mundo real

Um analista de dados tipicamente usa SQL para perguntar «me dê todas as sessões de 2023 com tarifa acima de 500» — extraindo os dados do banco de dados. Depois usa Python com pandas para limpá-los, calcular médias, e matplotlib para transformá-los em um gráfico. SQL extrai. Python analisa e visualiza.
