1. ¿Qué es SQL?

📂 Base de datos: photography_db

SQL significa Structured Query Language (lenguaje de consulta estructurado). Es el lenguaje que usa para hablar con una base de datos — para hacer preguntas, obtener datos, agregar nuevos registros, o hacer cambios.

Nuestra base de datos se llama photography_db. Contiene fotógrafos de 20 países, sus sesiones alrededor del mundo, y el equipo que poseen. Estos son los mismos datos usados en el curso de Python — dos lenguajes, un solo conjunto de datos.

Términos ClaveUna base de datos es una colección de datos organizados. Una tabla es un conjunto de datos relacionados dentro de ella. Una fila es un registro. Una columna es un dato sobre ese registro.

2. SELECT — Leer Datos

📂 Tabla: photographers

El comando SQL más importante es SELECT. Lo usará en casi todas las consultas que escriba. Le dice a la base de datos qué columnas quiere ver.

-- Obtener todas las columnas de la tabla photographers SELECT * FROM photographers;
-- Obtener solo el nombre y el país SELECT name, country FROM photographers;
Resultado
namecountry
Amara DialloSenegal
Carlos MendezBrazil
Priya NairIndia

-- Renombrar una columna en el resultado usando AS SELECT name AS photographer, specialty AS type_of_work, rating FROM photographers;
Use * con moderación. SELECT * retorna todas las columnas. Está bien para explorar, pero en consultas reales liste solo las columnas que realmente necesita.
Práctica

Escriba consultas que retornen:

  1. El nombre y la cámara de cada fotógrafo
  2. Todas las columnas de photographers — use *
  3. Nombre, especialidad y years_experience — renombre years_experience como experience

3. WHERE — Filtrar

📂 Tabla: shoots

WHERE filtra sus resultados. En lugar de cada fila, obtiene solo las filas que coinciden con su condición. Piense en ello como la pregunta después de «muéstrame solo...».

-- Solo las sesiones en Dakar SELECT event, location, year FROM shoots WHERE location = 'Dakar';
-- Solo las sesiones después de 2020 SELECT event, year, photos_taken FROM shoots WHERE year > 2020;
-- Combinar dos condiciones con AND SELECT event, location, year FROM shoots WHERE location = 'Dakar' AND year > 2020;
Resultado
eventlocationyear
Urban PortraitsDakar2024
Coastal Landscape SeriesDakar2024
Urban ArchitectureDakar2023
Conceptual SeriesDakar2023
Sunrise SeriesDakar2024
Operadores disponibles= (igual)  ·  != (diferente)  ·  > < >= <= (comparaciones)  ·  AND / OR (combinar)  ·  LIKE (coincidencia de patrón)  ·  IN (lista de valores)
-- LIKE — coincidencia parcial (% es un comodín) SELECT name, country FROM photographers WHERE name LIKE 'S%'; -- IN — coincide con cualquier valor de una lista SELECT name, country FROM photographers WHERE country IN ('USA', 'Brazil', 'Nigeria');
Los valores de texto necesitan comillas. Los números no. WHERE location = 'Dakar' — WHERE year > 2020. Confúndalos y obtendrá un error.

4. ORDER BY — Ordenar

📂 Tabla: shoots

ORDER BY ordena sus resultados. Por año, por nombre, por número de fotos. Ascendente (A→Z, más antiguo→más reciente) o descendente (más reciente→más antiguo, más alto→más bajo).

-- Las sesiones más recientes primero SELECT event, location, year FROM shoots ORDER BY year DESC;
-- Sesiones con más fotos tomadas, las más altas primero SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC;
-- Ordenar por dos columnas — primero año, luego nombre del evento SELECT event, location, year FROM shoots ORDER BY year DESC, event ASC;
Resultado
eventlocationyear
Bridal SessionKyiv2024
City NightsAccra2024
Coastal Landscape SeriesCasablanca2024
Coastal Landscape SeriesDakar2024
ASC = ascendente (por defecto, de menor a mayor, A a Z). DESC = descendente (de mayor a menor, Z a A). En caso de duda, agregue DESC para ver primero los valores más recientes o más altos.

5. LIMIT & DISTINCT

📂 Tabla: shoots · photographers

Dos comandos pequeños que usará constantemente. LIMIT controla cuántas filas recibe de vuelta. DISTINCT elimina valores duplicados.

LIMIT

-- Mostrar solo las 5 sesiones más recientes SELECT event, location, year FROM shoots ORDER BY year DESC LIMIT 5;
-- La única sesión con más fotos tomadas SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC LIMIT 1;

DISTINCT

-- ¿Qué países están representados? (sin duplicados) SELECT DISTINCT country FROM photographers ORDER BY country;
-- ¿Qué ubicaciones se han usado para sesiones? SELECT DISTINCT location FROM shoots ORDER BY location;

6. COUNT, AVG, MIN, MAX

📂 Tabla: shoots · photographers

Las funciones agregadas calculan valores a través de múltiples filas. En lugar de ver filas individuales, obtiene un único número resumen. Esencial para entender su archivo a gran escala.

-- ¿Cuántas sesiones hay en la base de datos? SELECT COUNT(*) AS total_shoots FROM shoots; -- Promedio de fotos tomadas por sesión SELECT AVG(photos_taken) AS avg_photos FROM shoots; -- Número más alto y más bajo de fotos en una sola sesión SELECT MAX(photos_taken) AS biggest_shoot, MIN(photos_taken) AS smallest_shoot FROM shoots;
Resultado
total_shootsavg_photosbiggest_shootsmallest_shoot
1036001,186119
-- Total de fotos exportadas en todas las sesiones SELECT SUM(photos_exported) AS total_exported FROM shoots; -- ¿Cuántos fotógrafos tienen calificación superior a 4.0? SELECT COUNT(*) AS top_rated FROM photographers WHERE rating > 4.0;
SUM · AVG · MAX · MIN · COUNT — estas cinco funciones responden la mayoría de las preguntas del mundo real sobre su archivo. ¿Cuánto? ¿Cuántos? ¿Cuál es el mejor? ¿Cuál es el peor?

7. GROUP BY & HAVING

📂 Tabla: shoots · photographers

GROUP BY agrupa filas para que pueda contar, sumar o promediar por categoría. En lugar de «cuántas sesiones en total» obtiene «cuántas sesiones por año» o «por ubicación».

-- ¿Cuántas sesiones por año? SELECT year, COUNT(*) AS shoots_that_year FROM shoots GROUP BY year ORDER BY year DESC;
Resultado
yearshoots_that_year
2024312
2023298
2022341
2021276
-- Promedio de fotos por sesión, agrupado por ubicación SELECT location, COUNT(*) AS total_shoots, ROUND(AVG(photos_taken), 0) AS avg_photos FROM shoots GROUP BY location ORDER BY total_shoots DESC;

HAVING — filtrar después de agrupar

WHERE filtra filas antes de agrupar. HAVING filtra grupos después de agrupar. Use HAVING cuando su condición involucre una función agregada.

-- Solo ubicaciones con más de 5 sesiones SELECT location, COUNT(*) AS shoot_count FROM shoots GROUP BY location HAVING COUNT(*) > 5 ORDER BY shoot_count DESC;
La reglaCada columna en SELECT que no está dentro de una función (COUNT, SUM, AVG) debe aparecer en GROUP BY. Si la selecciona, agrúpela.
WHERE vs HAVING: WHERE filtra filas antes de que se forme el grupo. HAVING filtra los grupos después de que se forman. En caso de duda — si su condición usa COUNT, SUM, AVG — use HAVING.

8. JOIN — Dos Tablas

📂 Tablas: photographers · shoots

JOIN conecta dos tablas usando una columna compartida. Aquí es donde SQL se vuelve verdaderamente poderoso — vinculando el nombre de un fotógrafo con todas sus sesiones, a través de dos tablas separadas.

-- Conectar sesiones con nombres de fotógrafos SELECT photographers.name, shoots.event, shoots.location, shoots.year FROM shoots JOIN photographers ON shoots.photographer_id = photographers.photographer_id ORDER BY shoots.year DESC LIMIT 5;
Resultado
nameeventlocationyear
Amara DialloWildlife Reserve ShootKyiv2024

Carlos MendezStreet Life SeriesLisbon2024
-- Usar alias de tabla para acortar las consultas SELECT p.name, s.event, s.year, s.photos_taken FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id WHERE s.year >= 2022 ORDER BY s.photos_taken DESC;
La clave compartidashoots.photographer_id coincide con photographers.photographer_id. Esa columna compartida es lo que conecta las dos tablas. Sin ella, el JOIN no tiene nada con qué coincidir.
Alias de tabla — dele a cada tabla una letra corta (p para photographers, s para shoots). Hace que las consultas largas sean mucho más fáciles de leer y escribir.

9. JOINs Múltiples

📂 Tablas: photographers · shoots · equipment

Puede hacer JOIN de más de dos tablas en una sola consulta. Cada JOIN agrega una conexión más. La clave siempre es una columna compartida entre dos tablas.

-- Fotógrafos + sus sesiones + el equipo usado SELECT p.name AS photographer, s.event, s.year, e.brand || ' ' || e.model AS camera FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id JOIN equipment e ON e.photographer_id = p.photographer_id WHERE e.type = 'Camera' ORDER BY s.year DESC LIMIT 10;
Resultado
photographereventyearcamera
Amara DialloWildlife Reserve Shoot2024Sony A7 IV
Sofia ReyesCoastal Landscape Series2024Nikon Z7 II
Carlos MendezRio Street Series2023Sony A7 IV
-- ¿Cuántas piezas de equipo posee cada fotógrafo? SELECT p.name, COUNT(e.item_id) AS gear_count, SUM(e.purchase_price_usd) AS total_invested FROM photographers p JOIN equipment e ON e.photographer_id = p.photographer_id GROUP BY p.name ORDER BY total_invested DESC;
Cada JOIN es un puente más. Primer puente: shoots → photographers. Segundo puente: equipment → photographers. El orden importa — cada nueva tabla debe compartir una columna con una ya presente en la consulta.

10. Subconsultas

📂 Tablas: photographers · shoots

Una subconsulta es una consulta dentro de otra consulta. Le permite usar el resultado de una pregunta como entrada para otra. La consulta interna se ejecuta primero y pasa su resultado a la consulta externa.

-- Encontrar todas las sesiones por encima del promedio de fotos SELECT event, location, photos_taken FROM shoots WHERE photos_taken > ( SELECT AVG(photos_taken) FROM shoots ) ORDER BY photos_taken DESC;
-- Fotógrafos que han hecho más de 5 sesiones SELECT name, country, specialty FROM photographers WHERE photographer_id IN ( SELECT photographer_id FROM shoots GROUP BY photographer_id HAVING COUNT(*) > 5 );

  2. Encuentre sesiones donde photos_exported sea mayor que el promedio general
  3. Encuentre fotógrafos que posean equipo con un costo total superior a $5,000

11. INSERT & UPDATE

📂 Tablas: photographers · shoots

Todo hasta ahora ha sido leer datos. INSERT agrega nuevas filas. UPDATE cambia las existentes. Estos son los comandos que usa para mantener su archivo actualizado.

INSERT — agregar un nuevo registro

-- Agregar una nueva sesión a la base de datos INSERT INTO shoots (photographer_id, event, location, year, photos_taken, photos_exported) VALUES (1, 'Nairobi Wildlife Assignment', 'Nairobi', 2025, 710, 115);
-- Agregar un nuevo fotógrafo INSERT INTO photographers (name, country, specialty, years_experience, rating) VALUES ('Grace Mwangi', 'Kenya', 'Wildlife', 8, 4.3);

UPDATE — cambiar datos existentes

-- Actualizar la calificación de un fotógrafo UPDATE photographers SET rating = 4.8 WHERE photographer_id = 1; -- Actualizar photos_exported para una sesión específica UPDATE shoots SET photos_exported = 112 WHERE shoot_id = 4471;
Use siempre WHERE con UPDATE. Sin WHERE, el UPDATE se aplica a todas las filas de la tabla. Eso casi nunca es lo que quiere. Verifique su condición WHERE con un SELECT antes de ejecutar un UPDATE.
