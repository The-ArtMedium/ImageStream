Your Own Archive
Is Now a Database

Everything in this course so far used a made-up dataset — a stand-in for a real photography archive, built so you could learn without pressure. This page is where that stops being make-believe. If you've used FocusCheck or AthleteTagger, some of your own photos are already sitting in a real, working database, right now, on your own machine.

What actually happened

FocusCheck and AthleteTagger have always done their job and then forgotten everything the moment they closed. FocusCheck would tell you a photo was sharp — and the instant the app shut, that judgment was gone. AthleteTagger would find Serena Williams in forty photos and rename them — and that knowledge lived nowhere except in the filenames themselves.

Now, quietly, both tools also write what they learn into one shared file: a small local database that lives at

# On Mac and Linux, this is a full path from your home folder. ~/Documents/LocalSuite/index.db

That's it. One file. No server, no account, no setup. It's the exact same kind of database — SQLite — that this course has been teaching you to query all along.

What's actually in it

One table, called photos. One row per photo. Each tool fills in whatever columns it knows about, and leaves the rest alone:

ColumnWho writes itWhat it means
filepathWhichever tool sees the photo firstWhere the file actually lives, right now
sharpness_verdictFocusChecksharp, fixable, or rejected
sharpness_scoreFocusCheckThe actual number behind that verdict
athlete_tagAthleteTaggerThe name matched in that photo, if any
thumbnail_pathWhichever tool sees the photo firstA small preview image, shared by every tool

The important part: if FocusCheck scores a photo sharp, and AthleteTagger later renames that same photo to tag an athlete in it — that's still one row, not two. Both facts live on the same photo. Renaming, moving, tagging — none of it splits the record in two or starts a new one by accident. That was tested deliberately, because it's the one thing that would have quietly broken the whole idea.

Nothing changes about how you use FocusCheck or AthleteTagger. You don't have to do anything differently. Run them exactly as you always have — the memory happens on its own, in the background, every time.

Try it on your own archive

Open ~/Documents/LocalSuite/index.db in any free SQLite browser (DB Browser for SQLite is a good one, and it's free), or use the sqlite3 command line if that's more your speed. Then ask it something real:

Every rejected photo you never actually deleted

SELECT filename, sharpness_score FROM photos WHERE sharpness_verdict = 'rejected';

How many sharp photos of one athlete you actually have

SELECT COUNT(*) FROM photos WHERE athlete_tag = 'Serena Williams' AND sharpness_verdict = 'sharp';

Your best photo of every athlete you've tagged so far

SELECT athlete_tag, filename, MAX(sharpness_score) AS best_score FROM photos WHERE athlete_tag IS NOT NULL GROUP BY athlete_tag;

That last one is the exact shape of query this course already taught you — GROUP BY, an aggregate function, a real question about real data. The only thing that changed is whose data it is.

About "syncing"

Right now: there isn't any, and that's on purpose, not a gap waiting to be filled.

The database is one plain file on one machine. Nothing to configure, nothing to connect, nothing that can leak, nothing that depends on a company staying in business. If you ever want your phone and your laptop to share the same archive knowledge, that's a real, separate decision — something to design deliberately once there's an actual reason for it, not something to bolt on now just because it sounds like the next feature. For today: it's yours, it's local, and it already works.

What's next

Right now, two tools write into this shared memory: FocusCheck and AthleteTagger. LocalRAW is next. Each tool that joins adds its own honest piece — nothing invented, nothing guessed, just what that tool already knows about a photo, given somewhere permanent to say it.

You don't need to wait for that. Every photo FocusCheck or AthleteTagger has already touched is queryable today, using exactly what you've already learned here.

Worth sitting with: a working archive isn't just personal convenience — it's proof. A photographer who can hand someone a searchable, organized body of work across years is showing something a folder full of loose files never can. That's not a small feature to add later. That's the difference between "I have some photos" and "here is my catalog." A detailed, queryable record of your own work is worth building for its own sake — not just to find one photo faster today.
