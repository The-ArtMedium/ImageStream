1. SQL क्या है?

📂 डेटाबेस: photography_db

SQL का मतलब है Structured Query Language। यह वह भाषा है जिससे आप डेटाबेस से बात करते हैं — सवाल पूछने, डेटा निकालने, नए रिकॉर्ड जोड़ने, या बदलाव करने के लिए।

हमारा डेटाबेस photography_db कहलाता है। इसमें 20 देशों के फ़ोटोग्राफ़र, दुनिया भर की उनकी शूट्स, और उनके उपकरण हैं। यह वही डेटा है जो Python कोर्स में इस्तेमाल होता है — दो भाषाएँ, एक डेटासेट।

मुख्य शब्दएक डेटाबेस व्यवस्थित डेटा का संग्रह है। एक टेबल उसके अंदर संबंधित डेटा का एक सेट है। एक पंक्ति (row) एक रिकॉर्ड है। एक कॉलम उस रिकॉर्ड की एक जानकारी है।

📂 टेबल: photographers

3. WHERE — फ़िल्टर करना

📂 टेबल: shoots

WHERE आपके नतीजों को फ़िल्टर करता है। हर पंक्ति के बजाय, आपको सिर्फ़ वे पंक्तियाँ मिलती हैं जो आपकी शर्त से मेल खाती हैं। इसे «मुझे सिर्फ़ यह दिखाओ...» के बाद आने वाला सवाल समझें।

-- सिर्फ़ डाकार की शूट्स SELECT event, location, year FROM shoots WHERE location = 'Dakar';
-- सिर्फ़ 2020 के बाद की शूट्स SELECT event, year, photos_taken FROM shoots WHERE year > 2020;
-- AND से दो शर्तों को जोड़ें SELECT event, location, year FROM shoots WHERE location = 'Dakar' AND year > 2020;

ऑपरेटर जो आप इस्तेमाल कर सकते हैं= (बराबर)  ·  != (बराबर नहीं)  ·  > < >= <= (तुलना)  ·  AND / OR (जोड़ना)  ·  LIKE (पैटर्न मैच)  ·  IN (मानों की सूची)
-- LIKE — आंशिक मेल (% एक वाइल्डकार्ड है) SELECT name, country FROM photographers WHERE name LIKE 'S%'; -- IN — सूची से किसी भी मान से मेल SELECT name, country FROM photographers WHERE country IN ('USA', 'Brazil', 'Nigeria');
टेक्स्ट मानों को कोट्स चाहिए। संख्याओं को नहीं। WHERE location = 'Dakar' — WHERE year > 2020। इन्हें मिला दें तो एरर आ जाएगा।

4. ORDER BY — क्रमबद्ध करना

📂 टेबल: shoots

ORDER BY आपके नतीजों को क्रमबद्ध करता है। साल के हिसाब से, नाम के हिसाब से, फ़ोटो की संख्या के हिसाब से। आरोही (A→Z, सबसे पुराना→सबसे नया) या अवरोही (सबसे नया→सबसे पुराना, सबसे ज़्यादा→सबसे कम)।

-- सबसे हाल की शूट्स पहले SELECT event, location, year FROM shoots ORDER BY year DESC;
-- सबसे ज़्यादा फ़ोटो वाली शूट्स, सबसे ज़्यादा पहले SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC;
-- दो कॉलम से क्रमबद्ध करें — पहले साल, फिर इवेंट का नाम SELECT event, location, year FROM shoots ORDER BY year DESC, event ASC;

5. LIMIT & DISTINCT

📂 टेबल: shoots · photographers

दो छोटे कमांड जिन्हें आप लगातार इस्तेमाल करेंगे। LIMIT यह तय करता है कि आपको कितनी पंक्तियाँ वापस मिलेंगी। DISTINCT दोहराए गए मान हटाता है।

LIMIT

-- सिर्फ़ 5 सबसे हाल की शूट्स दिखाएँ SELECT event, location, year FROM shoots ORDER BY year DESC LIMIT 5;
-- सबसे ज़्यादा फ़ोटो वाली एक शूट SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC LIMIT 1;

DISTINCT

-- कौन से देश शामिल हैं? (बिना दोहराव) SELECT DISTINCT country FROM photographers ORDER BY country;
-- शूट्स के लिए कौन से स्थान इस्तेमाल हुए हैं? SELECT DISTINCT location FROM shoots ORDER BY location;

6. COUNT, AVG, MIN, MAX

📂 टेबल: shoots · photographers

एग्रीगेट फ़ंक्शन कई पंक्तियों में मान की गणना करते हैं। अलग-अलग पंक्तियाँ देखने के बजाय, आपको एक सारांश संख्या मिलती है। बड़े पैमाने पर अपने आर्काइव को समझने के लिए ज़रूरी।

-- डेटाबेस में कितनी शूट्स हैं? SELECT COUNT(*) AS total_shoots FROM shoots; -- प्रति शूट औसत फ़ोटो SELECT AVG(photos_taken) AS avg_photos FROM shoots; -- एक शूट में सबसे ज़्यादा और सबसे कम फ़ोटो SELECT MAX(photos_taken) AS biggest_shoot, MIN(photos_taken) AS smallest_shoot FROM shoots;

7. GROUP BY & HAVING

📂 टेबल: shoots · photographers

GROUP BY पंक्तियों को समूहबद्ध करता है ताकि आप हर श्रेणी की गिनती, जोड़ या औसत निकाल सकें। «कुल कितनी शूट्स» के बजाय आपको «प्रति साल कितनी शूट्स» या «प्रति स्थान» मिलता है।

-- प्रति साल कितनी शूट्स? SELECT year, COUNT(*) AS shoots_that_year FROM shoots GROUP BY year ORDER BY year DESC;

-- प्रति शूट औसत फ़ोटो, स्थान अनुसार समूहबद्ध SELECT location, COUNT(*) AS total_shoots, ROUND(AVG(photos_taken), 0) AS avg_photos FROM shoots GROUP BY location ORDER BY total_shoots DESC;

HAVING — समूहबद्ध करने के बाद फ़िल्टर करना

WHERE समूहबद्ध करने से पहले पंक्तियों को फ़िल्टर करता है। HAVING समूहबद्ध करने के बाद समूहों को फ़िल्टर करता है। जब आपकी शर्त में एक एग्रीगेट फ़ंक्शन शामिल हो, तो HAVING इस्तेमाल करें।

-- सिर्फ़ वे स्थान जहाँ 5 से ज़्यादा शूट्स हुई हों SELECT location, COUNT(*) AS shoot_count FROM shoots GROUP BY location HAVING COUNT(*) > 5 ORDER BY shoot_count DESC;
नियमSELECT में हर वह कॉलम जो किसी फ़ंक्शन (COUNT, SUM, AVG) के अंदर नहीं है, उसे GROUP BY में ज़रूर आना चाहिए। अगर आप उसे SELECT करते हैं, तो उसे GROUP BY भी करें।
WHERE बनाम HAVING: WHERE समूह बनने से पहले पंक्तियों को फ़िल्टर करता है। HAVING समूह बनने के बाद उन्हें फ़िल्टर करता है। शक होने पर — अगर आपकी शर्त COUNT, SUM, AVG इस्तेमाल करती है — तो HAVING इस्तेमाल करें।

8. JOIN — दो टेबलें

📂 टेबलें: photographers · shoots

JOIN एक साझा कॉलम का उपयोग करके दो टेबलों को जोड़ता है। यहीं से SQL वाक़ई शक्तिशाली बनता है — दो अलग टेबलों में फैले एक फ़ोटोग्राफ़र के नाम को उसकी सभी शूट्स से जोड़ना।

-- शूट्स को फ़ोटोग्राफ़र के नामों से जोड़ें SELECT photographers.name, shoots.event, shoots.location, shoots.year FROM shoots JOIN photographers ON shoots.photographer_id = photographers.photographer_id ORDER BY shoots.year DESC LIMIT 5;

-- क्वेरीज़ को छोटा रखने के लिए टेबल alias इस्तेमाल करें SELECT p.name, s.event, s.year, s.photos_taken FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id WHERE s.year >= 2022 ORDER BY s.photos_taken DESC;
साझा कुंजीshoots.photographer_id, photographers.photographer_id से मेल खाता है। यही साझा कॉलम दोनों टेबलों को जोड़ता है। इसके बिना, JOIN के पास मिलाने के लिए कुछ नहीं होता।
टेबल alias — हर टेबल को एक छोटा अक्षर दें (p photographers के लिए, s shoots के लिए)। इससे लंबी क्वेरीज़ पढ़ना और लिखना बहुत आसान हो जाता है।

9. कई JOINs

📂 टेबलें: photographers · shoots · equipment

आप एक ही क्वेरी में दो से ज़्यादा टेबलों को JOIN कर सकते हैं। हर JOIN एक और कनेक्शन जोड़ता है। कुंजी हमेशा दो टेबलों के बीच एक साझा कॉलम होती है।

-- फ़ोटोग्राफ़र + उनकी शूट्स + इस्तेमाल किया गया उपकरण SELECT p.name AS photographer, s.event, s.year, e.brand || ' ' || e.model AS camera FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id JOIN equipment e ON e.photographer_id = p.photographer_id WHERE e.type = 'Camera' ORDER BY s.year DESC LIMIT 10;

-- हर फ़ोटोग्राफ़र के पास कितने उपकरण हैं? SELECT p.name, COUNT(e.item_id) AS gear_count, SUM(e.purchase_price_usd) AS total_invested FROM photographers p JOIN equipment e ON e.photographer_id = p.photographer_id GROUP BY p.name ORDER BY total_invested DESC;
हर JOIN एक और पुल है। पहला पुल: shoots → photographers। दूसरा पुल: equipment → photographers। क्रम मायने रखता है — हर नई टेबल को क्वेरी में पहले से मौजूद किसी टेबल के साथ एक कॉलम साझा करना ही होगा।

10. सब-क्वेरीज़

📂 टेबलें: photographers · shoots

सब-क्वेरी एक क्वेरी के अंदर एक क्वेरी है। यह आपको एक सवाल के नतीजे को दूसरे के इनपुट के रूप में इस्तेमाल करने देती है। भीतरी क्वेरी पहले चलती है और अपना नतीजा बाहरी क्वेरी को देती है।

-- औसत फ़ोटो गिनती से ऊपर की सभी शूट्स ढूँढें SELECT event, location, photos_taken FROM shoots WHERE photos_taken > ( SELECT AVG(photos_taken) FROM shoots ) ORDER BY photos_taken DESC;
-- वे फ़ोटोग्राफ़र जिन्होंने 5 से ज़्यादा शूट्स की हैं SELECT name, country, specialty FROM photographers WHERE photographer_id IN ( SELECT photographer_id FROM shoots GROUP BY photographer_id HAVING COUNT(*) > 5 );

अभ्यास

ये सब-क्वेरीज़ लिखने की कोशिश करें:

  1. औसत रेटिंग से ऊपर के सभी फ़ोटोग्राफ़र ढूँढें
  2. वे शूट्स ढूँढें जहाँ photos_exported कुल औसत से ज़्यादा है
  3. वे फ़ोटोग्राफ़र ढूँढें जिनके उपकरण की कुल क़ीमत $5,000 से ज़्यादा है

11. INSERT & UPDATE

📂 टेबलें: photographers · shoots

अब तक सब कुछ डेटा पढ़ना था। INSERT नई पंक्तियाँ जोड़ता है। UPDATE मौजूदा पंक्तियों को बदलता है। ये वे कमांड हैं जिनसे आप अपना आर्काइव अद्यतन रखते हैं।

INSERT — नया रिकॉर्ड जोड़ना

-- डेटाबेस में एक नई शूट जोड़ें INSERT INTO shoots (photographer_id, event, location, year, photos_taken, photos_exported) VALUES (1, 'Nairobi Wildlife Assignment', 'Nairobi', 2025, 710, 115);
-- एक नया फ़ोटोग्राफ़र जोड़ें INSERT INTO photographers (name, country, specialty, years_experience, rating) VALUES ('Grace Mwangi', 'Kenya', 'Wildlife', 8, 4.3);

UPDATE — मौजूदा डेटा बदलना

-- एक फ़ोटोग्राफ़र की रेटिंग अपडेट करें UPDATE photographers SET rating = 4.8 WHERE photographer_id = 1; -- किसी ख़ास शूट के लिए photos_exported अपडेट करें UPDATE shoots SET photos_exported = 112 WHERE shoot_id = 4471;
UPDATE के साथ हमेशा WHERE इस्तेमाल करें। WHERE के बिना, UPDATE टेबल की हर पंक्ति पर लागू हो जाता है। यह लगभग कभी वह नहीं होता जो आप चाहते हैं। UPDATE चलाने से पहले SELECT से अपनी WHERE शर्त जाँच लें।
पूरा SQL टूलकिटSELECT · WHERE · ORDER BY · LIMIT · DISTINCT · COUNT · AVG · SUM · MIN · MAX · GROUP BY · HAVING · JOIN · सब-क्वेरीज़ · INSERT · UPDATE। अपने पूरे फ़ोटोग्राफ़ी आर्काइव को क्वेरी करने, समझने, और बनाए रखने के लिए आपको बस इतना ही चाहिए।
अंतिम चुनौती

बिना पीछे देखे, ऐसी क्वेरीज़ लिखें जो:

  1. सभी शूट्स में ली गई कुल फ़ोटो के हिसाब से शीर्ष 5 फ़ोटोग्राफ़र दिखाएँ
  2. पिछले 3 सालों की उन सभी शूट्स को ढूँढें जिनमें 1,000 से ज़्यादा फ़ोटो ली गई — नाम, इवेंट, साल दिखाएँ
  3. प्रति स्थान कीपर रेट की गणना करें (photos_exported / photos_taken × 100) — सबसे ज़्यादा से क्रमबद्ध करें
  4. आपने जिस हाल के इवेंट को कवर किया, उसकी एक नई शूट डालें
