1. ما هو SQL؟

📂 قاعدة البيانات: photography_db

SQL تعني Structured Query Language (لغة الاستعلام المُهيكلة). هي اللغة التي تستخدمها للتحدث إلى قاعدة بيانات — لطرح الأسئلة، استرجاع البيانات، إضافة سجلات جديدة، أو إجراء تغييرات.

تُسمى قاعدة بياناتنا photography_db. تحتوي على مصورين من 20 دولة، جلساتهم حول العالم، والمعدات التي يمتلكونها. هذه نفس البيانات المستخدمة في دورة Python — لغتان، مجموعة بيانات واحدة.

مصطلحات أساسيةقاعدة البيانات هي مجموعة من البيانات المنظمة. الجدول مجموعة واحدة من البيانات المترابطة بداخلها. الصف سجل واحد. العمود معلومة واحدة عن ذلك السجل.

3. WHERE — التصفية

📂 الجدول: shoots

WHERE يُصفّي نتائجك. بدلاً من كل صف، تحصل فقط على الصفوف التي تطابق شرطك. فكّر فيه كالسؤال الذي يأتي بعد «أرني فقط...».

-- فقط الجلسات في داكار SELECT event, location, year FROM shoots WHERE location = 'Dakar';
-- فقط الجلسات بعد 2020 SELECT event, year, photos_taken FROM shoots WHERE year > 2020;
-- دمج شرطين باستخدام AND SELECT event, location, year FROM shoots WHERE location = 'Dakar' AND year > 2020;

عوامل يمكنك استخدامها= (يساوي)  ·  != (لا يساوي)  ·  > < >= <= (مقارنات)  ·  AND / OR (دمج)  ·  LIKE (مطابقة نمط)  ·  IN (قائمة قيم)
-- LIKE — مطابقة جزئية (% رمز بديل) SELECT name, country FROM photographers WHERE name LIKE 'S%'; -- IN — مطابقة أي قيمة من قائمة SELECT name, country FROM photographers WHERE country IN ('USA', 'Brazil', 'Nigeria');
القيم النصية تحتاج علامات اقتباس. الأرقام لا تحتاج. WHERE location = 'Dakar' — WHERE year > 2020. اخلطهما وستحصل على خطأ.

4. ORDER BY — الترتيب

📂 الجدول: shoots

ORDER BY يرتب نتائجك. حسب السنة، حسب الاسم، حسب عدد الصور. تصاعدي (A→Z، الأقدم→الأحدث) أو تنازلي (الأحدث→الأقدم، الأعلى→الأدنى).

-- الجلسات الأحدث أولاً SELECT event, location, year FROM shoots ORDER BY year DESC;
-- الجلسات ذات أكبر عدد صور، الأعلى أولاً SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC;
-- الترتيب حسب عمودين — السنة أولاً، ثم اسم الفعالية SELECT event, location, year FROM shoots ORDER BY year DESC, event ASC;
النتيجة

ASC = تصاعدي (الافتراضي، من الأصغر إلى الأكبر، A إلى Z). DESC = تنازلي (من الأكبر إلى الأصغر، Z إلى A). عند الشك، أضف DESC لرؤية القيم الأحدث أو الأعلى أولاً.

5. LIMIT & DISTINCT

📂 الجدول: shoots · photographers

أمران صغيران ستستخدمهما باستمرار. LIMIT يتحكم بعدد الصفوف التي تحصل عليها. DISTINCT يزيل القيم المكررة.

LIMIT

-- إظهار فقط أحدث 5 جلسات SELECT event, location, year FROM shoots ORDER BY year DESC LIMIT 5;
-- الجلسة الوحيدة ذات أكبر عدد صور SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC LIMIT 1;

DISTINCT

-- ما البلدان الممثَّلة؟ (بدون تكرار) SELECT DISTINCT country FROM photographers ORDER BY country;
-- ما المواقع التي استُخدمت للجلسات؟ SELECT DISTINCT location FROM shoots ORDER BY location;

6. COUNT, AVG, MIN, MAX

📂 الجدول: shoots · photographers

الدوال المجمِّعة تحسب القيم عبر صفوف متعددة. بدلاً من رؤية صفوف فردية، تحصل على رقم ملخص واحد. أساسي لفهم أرشيفك على نطاق واسع.

-- كم عدد الجلسات في قاعدة البيانات؟ SELECT COUNT(*) AS total_shoots FROM shoots; -- متوسط الصور الملتقطة لكل جلسة SELECT AVG(photos_taken) AS avg_photos FROM shoots; -- أعلى وأدنى عدد صور في جلسة واحدة SELECT MAX(photos_taken) AS biggest_shoot, MIN(photos_taken) AS smallest_shoot FROM shoots;
النتيجة

-- إجمالي الصور المُصدَّرة عبر كل الجلسات SELECT SUM(photos_exported) AS total_exported FROM shoots; -- كم عدد المصورين المقيَّمين فوق 4.0؟ SELECT COUNT(*) AS top_rated FROM photographers WHERE rating > 4.0;
SUM · AVG · MAX · MIN · COUNT — هذه الدوال الخمس تجيب على معظم الأسئلة الواقعية حول أرشيفك. كم؟ كم عدد؟ ما الأفضل؟ ما الأسوأ؟

7. GROUP BY & HAVING

📂 الجدول: shoots · photographers

GROUP BY يجمع الصفوف معاً حتى تتمكن من العد أو الجمع أو حساب المتوسط لكل فئة. بدلاً من «كم عدد الجلسات الإجمالي» تحصل على «كم جلسة لكل سنة» أو «لكل موقع».

-- كم جلسة لكل سنة؟ SELECT year, COUNT(*) AS shoots_that_year FROM shoots GROUP BY year ORDER BY year DESC;

-- متوسط الصور لكل جلسة، مجمّعة حسب الموقع SELECT location, COUNT(*) AS total_shoots, ROUND(AVG(photos_taken), 0) AS avg_photos FROM shoots GROUP BY location ORDER BY total_shoots DESC;

HAVING — التصفية بعد التجميع

WHERE يُصفّي الصفوف قبل التجميع. HAVING يُصفّي المجموعات بعد التجميع. استخدم HAVING عندما يتضمن شرطك دالة مجمِّعة.

-- فقط المواقع التي بها أكثر من 5 جلسات SELECT location, COUNT(*) AS shoot_count FROM shoots GROUP BY location HAVING COUNT(*) > 5 ORDER BY shoot_count DESC;
القاعدةكل عمود في SELECT ليس داخل دالة (COUNT، SUM، AVG) يجب أن يظهر في GROUP BY. إذا اخترته في SELECT، جمّعه في GROUP BY.
WHERE مقابل HAVING: WHERE يُصفّي الصفوف قبل تشكيل المجموعة. HAVING يُصفّي المجموعات بعد تشكيلها. عند الشك — إذا كان شرطك يستخدم COUNT أو SUM أو AVG — استخدم HAVING.

8. JOIN — جدولان

📂 الجداول: photographers · shoots

JOIN يربط جدولين معاً باستخدام عمود مشترك. هنا يصبح SQL قوياً حقاً — ربط اسم مصور بكل جلساته، عبر جدولين منفصلين.

-- ربط الجلسات بأسماء المصورين SELECT photographers.name, shoots.event, shoots.location, shoots.year FROM shoots JOIN photographers ON shoots.photographer_id = photographers.photographer_id ORDER BY shoots.year DESC LIMIT 5;
النتيجة
nameeventlocationyear

Carlos MendezStreet Life SeriesLisbon2024
-- استخدام ألقاب الجداول لتقصير الاستعلامات SELECT p.name, s.event, s.year, s.photos_taken FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id WHERE s.year >= 2022 ORDER BY s.photos_taken DESC;
المفتاح المشتركshoots.photographer_id يطابق photographers.photographer_id. هذا العمود المشترك هو ما يربط الجدولين. بدونه، لا يجد JOIN شيئاً ليطابقه.
ألقاب الجداول — أعطِ كل جدول حرفاً قصيراً (p لـ photographers، s لـ shoots). هذا يجعل الاستعلامات الطويلة أسهل بكثير للقراءة والكتابة.

9. عدة JOINs

📂 الجداول: photographers · shoots · equipment

يمكنك عمل JOIN لأكثر من جدولين في استعلام واحد. كل JOIN يضيف رابطاً إضافياً. المفتاح دائماً عمود مشترك بين جدولين.

-- المصورون + جلساتهم + المعدات المستخدمة SELECT p.name AS photographer, s.event, s.year, e.brand || ' ' || e.model AS camera FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id JOIN equipment e ON e.photographer_id = p.photographer_id WHERE e.type = 'Camera' ORDER BY s.year DESC LIMIT 10;

Carlos MendezRio Street Series2023Sony A7 IV
-- كم قطعة معدات يمتلك كل مصور؟ SELECT p.name, COUNT(e.item_id) AS gear_count, SUM(e.purchase_price_usd) AS total_invested FROM photographers p JOIN equipment e ON e.photographer_id = p.photographer_id GROUP BY p.name ORDER BY total_invested DESC;
كل JOIN هو جسر إضافي. الجسر الأول: shoots → photographers. الجسر الثاني: equipment → photographers. الترتيب مهم — كل جدول جديد يجب أن يشارك عموداً مع جدول موجود بالفعل في الاستعلام.

10. الاستعلامات الفرعية

📂 الجداول: photographers · shoots

الاستعلام الفرعي هو استعلام داخل استعلام. يتيح لك استخدام نتيجة سؤال واحد كمدخل لسؤال آخر. الاستعلام الداخلي يُنفَّذ أولاً ويمرر نتيجته إلى الاستعلام الخارجي.

-- إيجاد كل الجلسات فوق متوسط عدد الصور SELECT event, location, photos_taken FROM shoots WHERE photos_taken > ( SELECT AVG(photos_taken) FROM shoots ) ORDER BY photos_taken DESC;
-- المصورون الذين أجروا أكثر من 5 جلسات SELECT name, country, specialty FROM photographers WHERE photographer_id IN ( SELECT photographer_id FROM shoots GROUP BY photographer_id HAVING COUNT(*) > 5 );

11. INSERT & UPDATE

📂 الجداول: photographers · shoots

كل ما سبق كان قراءة بيانات. INSERT يضيف صفوفاً جديدة. UPDATE يغيّر الموجودة. هذه هي الأوامر التي تستخدمها للحفاظ على أرشيفك محدَّثاً.

INSERT — إضافة سجل جديد

-- إضافة جلسة جديدة إلى قاعدة البيانات INSERT INTO shoots (photographer_id, event, location, year, photos_taken, photos_exported) VALUES (1, 'Nairobi Wildlife Assignment', 'Nairobi', 2025, 710, 115);
-- إضافة مصور جديد INSERT INTO photographers (name, country, specialty, years_experience, rating) VALUES ('Grace Mwangi', 'Kenya', 'Wildlife', 8, 4.3);

UPDATE — تغيير بيانات موجودة

-- تحديث تقييم مصور واحد UPDATE photographers SET rating = 4.8 WHERE photographer_id = 1; -- تحديث photos_exported لجلسة معينة UPDATE shoots SET photos_exported = 112 WHERE shoot_id = 4471;
استخدم WHERE دائماً مع UPDATE. بدون WHERE، يُطبَّق UPDATE على كل صف في الجدول. هذا نادراً ما يكون ما تريده. تحقق من شرط WHERE باستخدام SELECT أولاً قبل تشغيل UPDATE.
