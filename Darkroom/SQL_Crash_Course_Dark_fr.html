1. Qu'est-ce que SQL ?

📂 Base de données : photography_db

SQL signifie Structured Query Language (langage de requête structuré). C'est le langage que vous utilisez pour parler à une base de données — poser des questions, récupérer des données, ajouter de nouveaux enregistrements, ou faire des modifications.

Notre base de données s'appelle photography_db. Elle contient des photographes de 20 pays, leurs séances à travers le monde, et l'équipement qu'ils possèdent. Ce sont les mêmes données que celles utilisées dans le cours Python — deux langages, un seul jeu de données.

Termes ClésUne base de données est un ensemble de données organisées. Une table est un ensemble de données liées à l'intérieur. Une ligne est un enregistrement. Une colonne est une information sur cet enregistrement.

2. SELECT — Lire les Données

📂 Table : photographers

La commande SQL la plus importante est SELECT. Vous l'utiliserez dans presque toutes les requêtes que vous écrirez. Elle indique à la base de données quelles colonnes vous voulez voir.

-- Récupérer toutes les colonnes de la table photographers SELECT * FROM photographers;
-- Récupérer seulement le nom et le pays SELECT name, country FROM photographers;
Résultat
namecountry
Amara DialloSenegal
Carlos MendezBrazil
Priya NairIndia
James OkonkwoNigeria
-- Renommer une colonne dans le résultat avec AS SELECT name AS photographer, specialty AS type_of_work, rating FROM photographers;
Utilisez * avec parcimonie. SELECT * retourne toutes les colonnes. C'est bien pour explorer, mais dans de vraies requêtes, ne listez que les colonnes dont vous avez réellement besoin.

3. WHERE — Filtrer

📂 Table : shoots

WHERE filtre vos résultats. Au lieu de chaque ligne, vous n'obtenez que les lignes qui correspondent à votre condition. Pensez-y comme la question après « montre-moi seulement... ».

-- Seulement les séances à Dakar SELECT event, location, year FROM shoots WHERE location = 'Dakar';
-- Seulement les séances après 2020 SELECT event, year, photos_taken FROM shoots WHERE year > 2020;
-- Combiner deux conditions avec AND SELECT event, location, year FROM shoots WHERE location = 'Dakar' AND year > 2020;
Résultat
eventlocationyear
Urban PortraitsDakar2024
Coastal Landscape SeriesDakar2024
Urban ArchitectureDakar2023
Conceptual SeriesDakar2023
Sunrise SeriesDakar2024
Opérateurs disponibles= (égal)  ·  != (différent)  ·  > < >= <= (comparaisons)  ·  AND / OR (combiner)  ·  LIKE (motif)  ·  IN (liste de valeurs)
-- LIKE — correspondance partielle (% est un joker) SELECT name, country FROM photographers WHERE name LIKE 'S%'; -- IN — correspond à n'importe quelle valeur d'une liste SELECT name, country FROM photographers WHERE country IN ('USA', 'Brazil', 'Nigeria');
Les valeurs texte ont besoin de guillemets. Pas les nombres. WHERE location = 'Dakar' — WHERE year > 2020. Mélangez-les et vous obtenez une erreur.

4. ORDER BY — Trier

📂 Table : shoots

ORDER BY trie vos résultats. Par année, par nom, par nombre de photos. Croissant (A→Z, le plus ancien→le plus récent) ou décroissant (le plus récent→le plus ancien, le plus élevé→le plus bas).

-- Les séances les plus récentes en premier SELECT event, location, year FROM shoots ORDER BY year DESC;
-- Les séances avec le plus de photos prises, les plus élevées en premier SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC;
-- Trier par deux colonnes — année d'abord, puis nom de l'événement SELECT event, location, year FROM shoots ORDER BY year DESC, event ASC;
Résultat
eventlocationyear
Bridal SessionKyiv2024
City NightsAccra2024
Coastal Landscape SeriesCasablanca2024
Coastal Landscape SeriesDakar2024
ASC = croissant (par défaut, du plus petit au plus grand, A à Z). DESC = décroissant (du plus grand au plus petit, Z à A). En cas de doute, ajoutez DESC pour voir les valeurs les plus récentes ou les plus élevées en premier.

5. LIMIT & DISTINCT

📂 Table : shoots · photographers

Deux petites commandes que vous utiliserez constamment. LIMIT contrôle le nombre de lignes retournées. DISTINCT supprime les valeurs en double.

LIMIT

-- Montrer seulement les 5 séances les plus récentes SELECT event, location, year FROM shoots ORDER BY year DESC LIMIT 5;
-- La seule séance avec le plus de photos prises SELECT event, photos_taken FROM shoots ORDER BY photos_taken DESC LIMIT 1;

DISTINCT

-- Quels pays sont représentés ? (sans doublons) SELECT DISTINCT country FROM photographers ORDER BY country;
-- Quels lieux ont été utilisés pour des séances ? SELECT DISTINCT location FROM shoots ORDER BY location;
Résultat

Accra

Bogotá

Utilisez toujours LIMIT quand vous explorez une table pour la première fois. Même avec 103 lignes, cela garde votre écran lisible — et cette habitude compte encore plus une fois que votre vraie archive atteint des milliers d'entrées.

6. COUNT, AVG, MIN, MAX

📂 Table : shoots · photographers

Les fonctions d'agrégation calculent des valeurs à travers plusieurs lignes. Au lieu de voir des lignes individuelles, vous obtenez un seul nombre récapitulatif. Essentiel pour comprendre votre archive à grande échelle.

-- Combien de séances dans la base de données ? SELECT COUNT(*) AS total_shoots FROM shoots; -- Moyenne de photos prises par séance SELECT AVG(photos_taken) AS avg_photos FROM shoots; -- Nombre de photos le plus élevé et le plus bas pour une seule séance SELECT MAX(photos_taken) AS biggest_shoot, MIN(photos_taken) AS smallest_shoot FROM shoots;
Résultat
total_shootsavg_photosbiggest_shootsmallest_shoot
1036001,186119
-- Total de photos exportées sur toutes les séances SELECT SUM(photos_exported) AS total_exported FROM shoots; -- Combien de photographes sont notés au-dessus de 4.0 ? SELECT COUNT(*) AS top_rated FROM photographers WHERE rating > 4.0;
SUM · AVG · MAX · MIN · COUNT — ces cinq fonctions répondent à la plupart des questions concrètes sur votre archive. Combien ? Combien de fois ? Quel est le meilleur ? Quel est le pire ?

7. GROUP BY & HAVING

📂 Table : shoots · photographers

GROUP BY regroupe les lignes ensemble pour que vous puissiez compter, sommer ou faire la moyenne par catégorie. Au lieu de « combien de séances au total », vous obtenez « combien de séances par année » ou « par lieu ».

-- Combien de séances par année ? SELECT year, COUNT(*) AS shoots_that_year FROM shoots GROUP BY year ORDER BY year DESC;
Résultat
yearshoots_that_year
2024312
2023298
2022341
2021276
-- Moyenne de photos par séance, groupée par lieu SELECT location, COUNT(*) AS total_shoots, ROUND(AVG(photos_taken), 0) AS avg_photos FROM shoots GROUP BY location ORDER BY total_shoots DESC;

HAVING — filtrer après le regroupement

WHERE filtre les lignes avant le regroupement. HAVING filtre les groupes après le regroupement. Utilisez HAVING quand votre condition implique une fonction d'agrégation.

-- Seulement les lieux avec plus de 5 séances SELECT location, COUNT(*) AS shoot_count FROM shoots GROUP BY location HAVING COUNT(*) > 5 ORDER BY shoot_count DESC;
La règleChaque colonne dans SELECT qui n'est pas à l'intérieur d'une fonction (COUNT, SUM, AVG) doit apparaître dans GROUP BY. Si vous la sélectionnez, groupez-la.
WHERE vs HAVING : WHERE filtre les lignes avant que le groupe soit formé. HAVING filtre les groupes après leur formation. En cas de doute — si votre condition utilise COUNT, SUM, AVG — utilisez HAVING.

8. JOIN — Deux Tables

📂 Tables : photographers · shoots

JOIN relie deux tables ensemble en utilisant une colonne commune. C'est ici que SQL devient vraiment puissant — relier le nom d'un photographe à toutes ses séances, à travers deux tables séparées.

-- Relier les séances aux noms des photographes SELECT photographers.name, shoots.event, shoots.location, shoots.year FROM shoots JOIN photographers ON shoots.photographer_id = photographers.photographer_id ORDER BY shoots.year DESC LIMIT 5;
Résultat
nameeventlocationyear
Amara DialloWildlife Reserve ShootKyiv2024
Carlos MendezUrban PortraitsSão Paulo2024
Carlos MendezMarket DayBerlin2024
Carlos MendezStreet Life SeriesLisbon2024
-- Utiliser des alias de table pour raccourcir les requêtes SELECT p.name, s.event, s.year, s.photos_taken FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id WHERE s.year >= 2022 ORDER BY s.photos_taken DESC;
La clé communeshoots.photographer_id correspond à photographers.photographer_id. Cette colonne commune est ce qui relie les deux tables. Sans elle, le JOIN n'a rien pour établir la correspondance.
Alias de table — donnez à chaque table une lettre courte (p pour photographers, s pour shoots). Cela rend les requêtes longues beaucoup plus faciles à lire et à écrire.

9. JOINs Multiples

📂 Tables : photographers · shoots · equipment

Vous pouvez faire un JOIN de plus de deux tables dans une seule requête. Chaque JOIN ajoute une connexion supplémentaire. La clé est toujours une colonne commune entre deux tables.

-- Photographes + leurs séances + l'équipement utilisé SELECT p.name AS photographer, s.event, s.year, e.brand || ' ' || e.model AS camera FROM shoots s JOIN photographers p ON s.photographer_id = p.photographer_id JOIN equipment e ON e.photographer_id = p.photographer_id WHERE e.type = 'Camera' ORDER BY s.year DESC LIMIT 10;
Résultat
photographereventyearcamera
Amara DialloWildlife Reserve Shoot2024Sony A7 IV
Sofia ReyesCoastal Landscape Series2024Nikon Z7 II
Carlos MendezRio Street Series2023Sony A7 IV
-- Combien de pièces d'équipement chaque photographe possède-t-il ? SELECT p.name, COUNT(e.item_id) AS gear_count, SUM(e.purchase_price_usd) AS total_invested FROM photographers p JOIN equipment e ON e.photographer_id = p.photographer_id GROUP BY p.name ORDER BY total_invested DESC;
Chaque JOIN est un pont de plus. Premier pont : shoots → photographers. Deuxième pont : equipment → photographers. L'ordre compte — chaque nouvelle table doit partager une colonne avec une table déjà présente dans la requête.

10. Sous-requêtes

📂 Tables : photographers · shoots

Une sous-requête est une requête à l'intérieur d'une requête. Elle vous permet d'utiliser le résultat d'une question comme donnée d'entrée pour une autre. La requête interne s'exécute en premier et transmet son résultat à la requête externe.

-- Trouver toutes les séances au-dessus du nombre moyen de photos SELECT event, location, photos_taken FROM shoots WHERE photos_taken > ( SELECT AVG(photos_taken) FROM shoots ) ORDER BY photos_taken DESC;
-- Photographes ayant fait plus de 5 séances SELECT name, country, specialty FROM photographers WHERE photographer_id IN ( SELECT photographer_id FROM shoots GROUP BY photographer_id HAVING COUNT(*) > 5 );

11. INSERT & UPDATE

📂 Tables : photographers · shoots

Tout ce que nous avons vu jusqu'ici consistait à lire des données. INSERT ajoute de nouvelles lignes. UPDATE modifie celles qui existent déjà. Ce sont les commandes que vous utilisez pour garder votre archive à jour.

INSERT — ajouter un nouvel enregistrement

-- Ajouter une nouvelle séance à la base de données INSERT INTO shoots (photographer_id, event, location, year, photos_taken, photos_exported) VALUES (1, 'Nairobi Wildlife Assignment', 'Nairobi', 2025, 710, 115);
-- Ajouter un nouveau photographe INSERT INTO photographers (name, country, specialty, years_experience, rating) VALUES ('Grace Mwangi', 'Kenya', 'Wildlife', 8, 4.3);

UPDATE — modifier des données existantes

-- Mettre à jour la note d'un photographe UPDATE photographers SET rating = 4.8 WHERE photographer_id = 1; -- Mettre à jour photos_exported pour une séance spécifique UPDATE shoots SET photos_exported = 112 WHERE shoot_id = 4471;
Utilisez toujours WHERE avec UPDATE. Sans WHERE, l'UPDATE s'applique à toutes les lignes de la table. Ce n'est presque jamais ce que vous voulez. Vérifiez votre condition WHERE avec un SELECT avant d'exécuter un UPDATE.
La boîte à outils SQL complèteSELECT · WHERE · ORDER BY · LIMIT · DISTINCT · COUNT · AVG · SUM · MIN · MAX · GROUP BY · HAVING · JOIN · Sous-requêtes · INSERT · UPDATE. C'est tout ce dont vous avez besoin pour interroger, comprendre et maintenir toute votre archive photographique.
